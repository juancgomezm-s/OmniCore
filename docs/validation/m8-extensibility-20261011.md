# M8 Extensibility — baseline and delivery sequence

Plataforma de trabajo Windows; validación M8 parcial y pendiente de cierre. Actualizado 2026-10-11. Rama `codex/m8-extensibility-20261011`, basada en `main` (`e3cae2f0f35d230baeb1e72fd83041620bc476dd`). M7 está cerrado en Windows; M8 todavía no.

## Matriz de base

| Área | Hecho reutilizable | Falta para M8 |
|---|---|---|
| Grafo y límites | `OmniCore.Extensions` ya depende solo de Abstractions y Domain; Host compone; CLI usa Host solo en composición y Protocol/Client para rutas; graph test pasa. | Mantener `CLI → Domain` prohibido al ampliar capacidades. |
| Origen y confianza | `SourceKind`, `TrustLevel`, `ScopeLevel`, `ComponentSource`, `ToolDescriptor.Source/Protection/EffectClass` y `ContextItemKind.Memory`; `ExtensionConsentStore` local al Workspace ata consentimiento de capabilities a id/version/SHA256 de manifest y archivos regulares del paquete. Esos consentimientos no son grants de `PermissionPolicy`. | MCP local/proyecto/remoto y procedencia completa; fuentes Extension Trusted/User aún no se cargan. |
| Tool runtime | `ExtensionBoundary` implementa `IToolIntentBoundary` y se evalúa antes del motor de permisos y otra vez antes de Execute. `ExtensionTool` declara process/read/write/network claims desde el manifest; Host recibe solo `AuthorizedToolIntent`. Strong concede acceso solo a archivos regulares existentes que coinciden con paths autorizados dentro del Workspace, sin enlaces/reparse points. | Network claims se rechazan en Strong porque AppContainer no puede imponer allowlist exacta por host; los write claims solo pueden alcanzar archivos existentes. Mantener restricciones parent/model/user en intersección y agregar soporte cuando el sandbox imponga cada destino de forma precisa. |
| Commands | Contratos `CommandDescriptor`/`ICommandHandler`, `CommandRegistry`, query Host `commands`, autocompletado del Client; `/extensions`, `/commands`, `/skills`, `/memory session` y `omni extensions trust|revoke <id>` están conectados a Host/Client. El registry resuelve por scope más específico y deja el nombre ambiguo si esa fuente tiene menos confianza que otra candidata; `/commands` muestra la razón y el id canónico sigue resolviendo. Los ExtensionCommands Project consentidos asocian un command a una tool declarada y fuerzan esa tool en la primera llamada del Turn normal. | Alias explícito de User y diagnósticos completos de precedencia. Un command es una intención, nunca inicia un proceso en el handler; la tool sigue la autorización, Barrier y Strong del ToolRuntime. |
| Skills | `SkillManifestLoader` Project exige workspace confiable y solo inspecciona `skill.yaml`; evalúa activadores de paths/extensiones/language/framework/taskType; aplica precedencia y reglas `sealed`/trust; `/skills` muestra metadata sin leer instructions; `/skills load|release <id>` gestiona selección persistente por `SessionId` y hash del manifest. `OmniCliRuntime` carga únicamente las seleccionadas, verifica el hash de nuevo, contribuye `ContextItemKind.Skill` con procedencia y publica `ActiveSkillFingerprint` del contenido efectivo. | Scopes BuiltIn/User/Workspace/Session configurables, índice de elegibles/modelInvocable, tools/workflows/validators/contributors/knowledge aportados por skill; aislamiento fino de otros archivos del paquete. |
| Hooks | Contrato arquitectónico ADR-0020 define capacidades y `HookResult` solo restrictivos. | Tipos/runtime de hooks, dispatch con filtrado/redacción, consentimiento/capacidades, fall closed para restricción/validación y fail open para observación/anotación. |
| MCP | ADR-0023 define niveles y techos por origen. | Adaptador MCP local/remoto con TrustLevel, techo de configuración, consentimiento, primer uso Ask para tools con efecto y redacción saliente para remoto. |
| Tool preferences | Las reglas de ADR-0027 ya especifican ids canónicos, protección y preferencia explícita más Ask si sustituye tool protegida. | Persistir/resolver `toolPreferences`, aplicar al planner, fingerprint y diagnóstico. |
| Memoria | `OmniCore.Memory` implementa `IMemoryStore` Session durable y separado de `WorkingState`; `SessionMemoryContextContributor` recupera únicamente la sesión actual, filtra expiración, deduplica por contenido normalizado, ordena por fuente/score/recencia y limita 24 items/12,000 caracteres con `ContextItemKind.Memory` y procedencia. `OmniServer` valida trusted user action, rechaza patrones de secretos antes de persistir, y admite `/memory session`, `add` y `forget`. El store valida `Supersedes` dentro de la Session, rechaza referencias ausentes, reemplazos ramificados o ciclos; el contexto omite antecesores reemplazados y `forget` colapsa la cadena. `ExplorerTurn.RenderContext` entrega Memory al modelo y, tras `ModelStepCompleted`, el Host actualiza `LastUsedAt` solo para los items de memoria en el snapshot del paso. | Política de candidatos/promotion/Ask y scopes Project/Workspace/Global (M10). |
| CLI/diagnóstico | Host expone `commands`, `/extensions` muestra discovery/trust/consent; `omni extensions trust|revoke <id>` grava grants locales; `/commands` muestra precedencia/conflictos; `/skills` descubre, lista, activa y libera Project skills; `/memory session [add|forget]` consulta y modifica la memoria de Session por trusted user action; `/tools` existente. | Precedencia configurable por alias User y diagnósticos integrales de hooks/MCP/preferences. |

## Secuencia de entregas M8

1. **Extension foundation:** `OmniCore.Extensions`, manifest YAML tipado/versionado y validado, discovery de directorios aplicables, estados de compatibilidad/trust y `ExtensionBoundary` intersectada con los permisos parent; proceso externo JSON-RPC con fixture real y tool registrada/cableada Host→CLI. Salida: manifest inválido/incompatible no se ejecuta; workspace Project no confiable no descubre/ejecuta extensiones; un intent fuera del techo se deniega antes de consentimiento; reabrir Host conserva discovery/configuración y no cambia el aislamiento.
2. **Commands and skills:** precedencia base de commands por scope/confianza, ruta `/commands` e invocación de `ExtensionCommand`→tool declarada completadas parcialmente; aliases explícitos y `toolPreferences` con fingerprint/ruta al planner siguen pendientes. Skills Project confiables ahora tienen discovery, activación/liberación por sesión, precedence base, contributor y fingerprint; siguen pendientes scopes adicionales, índice/model invocation y aportes de tools/validators/knowledge. Salida final: comandos conflictivos reportados; preferencias protegidas requieren Ask; skills descubiertas no consumen contexto sin activación.
3. **Hooks and MCP:** capabilities explícitas por componente, despacho de hooks restrictivos con error policy, MCP local/proyecto/remoto con confianza, techo y primer uso Ask. Salida: HookResult no puede ampliar; fallos restrictivos/validación deniegan; MCP remoto no expone argumentos sin redactor; permiso MCP nunca rebasa el techo.
4. **Session Memory and commands:** contrato/almacenamiento durable por Session, contributor con slot Memory independiente de WorkingState y `/memory session` se implementaron parcialmente con almacenamiento UserStated explícito; falta candidato/política de promoción, `Supersedes`, actualización de `LastUsedAt` e integración al flujo de candidaturas. `/extensions`, `/skills` y catálogo efectivo `/commands` ya tienen rutas CLI. Salida de esta entrega: persistencia tras reabrir, aislamiento entre sesiones, filtros/procedencia y budget respetado.
5. **Integración M8:** pruebas focales cruzadas Host/CLI/confianza/aislamiento, arquitectura, build Windows multi-target apropiado y suite integral al cierre. Project/Workspace/Global Memory y transporte cliente/Host entre procesos pertenecen a M10 y M9 respectivamente.

## Estado del checkpoint

La entrega de commands añade `/commands` a `ClientCommandRegistry` y `ClientActionHandler`, consulta el catálogo wire-safe del Host y resuelve nombres cortos por precedencia de scope con la restricción de confianza de ADR-0024. La entrega de skills conecta discovery Project, `/skills load|release`, selección durable por sesión y materialización/fingerprint real de instrucciones activadas. Session Memory ahora tiene `OmniCore.Memory`, archivo atómico por SessionId, dedupe, expiración, retrieval aislado/presupuestado, contributor con `ContextItemKind.Memory` y `/memory session [add|forget]` que requiere acción de usuario confiable. Los comandos operan por `IOmniClient` y no eluden el Host.

Discovery y Prepare no lanzan procesos. En Act, el Host registra solo `ExtensionTool` de paquetes Project confiables con consentimiento ligado a hashes. El intent declara claims del manifest; la política parent/model/user todavía puede denegar o pedir Ask. Sin respuesta a Ask, no hay RPC. Tras aprobación, la bridge pasa los claims autorizados a un launcher Strong sin fallback; revalida manifest/package hashes antes de iniciar. El runtime solo obtiene lectura de su paquete más ACL por archivo regular existente dentro del Workspace para cada claim Read/Write autorizado. El test de JSON-RPC malformado/error/timeout usa un launcher fixture para aislar respuestas; no se presenta como ejecución Strong real. El Strong real está probado por separado con el proceso fixture. La validación de Linux queda diferida, sin afirmaciones de soporte multiplataforma.
