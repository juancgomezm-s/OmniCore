## Secuencia de entregas M8

1. **Extension foundation:** `OmniCore.Extensions`, manifest YAML tipado/versionado y validado, discovery de directorios aplicables, estados de compatibilidad/trust y `ExtensionBoundary` intersectada con los permisos parent; proceso externo JSON-RPC con fixture real y tool registrada/cableada Host→CLI. Salida: manifest inválido/incompatible no se ejecuta; workspace Project no confiable no descubre/ejecuta extensiones; un intent fuera del techo se deniega antes de consentimiento; reabrir Host conserva discovery/configuración y no cambia el aislamiento.
2. **Commands and skills:** precedencia base de commands por scope/confianza, ruta `/commands` e invocación de `ExtensionCommand`→tool declarada completadas parcialmente; aliases explícitos y `toolPreferences` con fingerprint/ruta al planner siguen pendientes. Skills Project confiables ahora tienen discovery, activación/liberación por sesión, precedence base, contributor y fingerprint; siguen pendientes scopes adicionales, índice/model invocation y aportes de tools/validators/knowledge. Salida final: comandos conflictivos reportados; preferencias protegidas requieren Ask; skills descubiertas no consumen contexto sin activación.
3. **Hooks and MCP:** capabilities explícitas por componente, despacho de hooks restrictivos con error policy, MCP local/proyecto/remoto con confianza, techo y primer uso Ask. Salida: HookResult no puede ampliar; fallos restrictivos/validación deniegan; MCP remoto no expone argumentos sin redactor; permiso MCP nunca rebasa el techo.
4. **Session Memory and commands:** almacenamiento durable UserStated y `/memory session`, contributor aislado/presupuestado y Supersedes integrados; cableado al modelo, LastUsedAt y defensa de ruta en rama. Integrar/verificar ese delta y completar candidatos/política/promoción/Ask y auditoría. `/extensions`, `/skills` y catálogo efectivo `/commands` ya tienen rutas CLI; se reutilizan sus páginas/idiomas de preferencias. Salida: persistencia/reapertura, uso efectivo como dato, aislamiento, filtros/budget y decisiones visibles en es/en/fr/it sin alterar el contenido.
5. **Integración M8:** pruebas focales cruzadas Host/CLI/confianza/aislamiento, arquitectura, build Windows multi-target apropiado y suite integral al cierre. Project/Workspace/Global Memory y transporte cliente/Host entre procesos pertenecen a M10 y M9 respectivamente.

### Checkpoint M8: lectura paginada y descubrimiento de tools

Implementado en el delta actual, pendiente de revisión y sin afirmar cierre de M8:

- `filesystem.read` acepta `offset` (base 1) y `limit` (por defecto 200, máximo 500), conserva el hash SHA-256 del archivo entero y devuelve marcador con rango, total, continuación y truncado del contenido. La redacción se aplica antes de devolver cada página.
- Una página exitosa que expone el hash del archivo completo registra la misma evidencia path+versión que el contrato vigente de `FileReadRegistry`; el patch sigue sujeto al `oldText` exacto, hash actual y permisos existentes. No se requiere leer todas las páginas antes de un patch. El resultado nunca declara que una página sea el contenido íntegro del archivo.
- Las páginas preservan los terminadores decodificados originales (LF/CRLF mixtos incluidos), de modo que un fragmento multilinea puede pasarse literalmente a `filesystem.patch`. Una línea individual superior a 8,000 caracteres conserva truncado y `hasMore` como señal fail-closed, pero no tiene continuación intralínea; no se afirma que ese contenido pueda recuperarse con otro `offset`.
