Delivered contracts and runtime wiring
--------------------------------------
RunSummary and run.summary_recorded v1 provide a structured, redacted CAS receipt
with Session/Run identity and exact terminal-event coverage. The Host records it
after real completion or terminal commands; a subsequent Ask backfills a missing
receipt for older journals/crash recovery. Active/rejected completion is not
converted into a terminal Run. Completion gates and authority are unchanged.
Summary generation is an offline projection and does not call a provider.

Only principal-lane user/assistant conversation is inherited from prior Runs.
Child-lane input, assistant output and checkpoints are excluded; raw tool results
remain Run-local. Legacy principal-lane ModelCompleted text is retained when a
journal predates AssistantMessageRecorded. A principal checkpoint contributes
only its verified receipt/hash: its body can contain tools/reasoning and is NOT
copied into subsequent-Run conversation.

When the existing budget policy would omit/truncate prior history, the affected
Run contributes its summary as factual data with Run/event/CAS provenance. The
original transcript is retained when it fits. Summaries cannot replace fresh
WorkingState and are not instructions or authority. Artifact roots are explicit
in both the event payload and envelope; GC retention and reopen are tested.
v1 still assumes the existing single canonical writer; multiwriter coordination
is not claimed. Read validation rejects mismatched identity/source sequence,
missing/corrupt CAS and duplicate roots instead of silently trusting them.

Additional real defect found and fixed
-------------------------------------
With enough historical summaries, budget selection evicted the NEW user message
and submitted only the first historical goal. With an oversized new input it
likewise submitted a request without that input instead of rejecting overflow.
Two focused regressions reproduced this (both FAIL before the input guard).
The most recent user input is now protected alongside the existing first input,
System and WorkingState. If protected content cannot fit, ContextOverflow stops
dispatch; the provider is not invoked with a silently missing current intent.

Protecting the new input initially shifted checkpoint cadence. The first broad
run recorded 3057 cases / 3 FAIL / 4 SKIP; failures were the existing checkpoint
publication/failed-publication and reopen regressions. Their assertions were NOT
weakened. Current input still occupies its configured recent-tail position and
may inform a checkpoint, but its original message is never removed. A checkpoint
is not generated repeatedly for protected input alone. The failed run is preserved
as .tmp-run-summary-full.log for audit, not counted as successful validation.
