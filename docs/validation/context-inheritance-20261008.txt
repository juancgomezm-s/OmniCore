Delivered runtime boundaries
----------------------------
LaneConversationScope resolves canonical Lane/Turn/ToolCall identities. A child
has its own Run-local transcript, not the principal's Session conversation.
Legacy ownership is inferred only from exact receipts or an unambiguous one-Lane
Run; no ambient/last-event cursor is used as read authority. Conflicts fail closed.
Checkpoints select their own Lane and persist laneId/local compaction indices.
Ambiguous old multi-Lane checkpoints are ignored and rebuilt from scoped history.
Context materialization passes the actual Task identity to contributors.
Snapshots add contextScopeVersion=1 and Session/Run/Task/Lane/Turn identities.

ContextInheritancePolicy freezes explicit unique item IDs; default selects nothing.
ContextInheritanceService is read-only. It validates a direct parent/child link and
the parent's canonical ModelStepStarted snapshot receipt, CAS integrity and body
scope. Allowed subset: non-sensitive shared Conversation/Task factual data in
Session/Run scope, selected by ID. All other data is rejected, not silently copied.
Parent System/WorkingState, tools, checkpoints, private Task/Lane data, file bodies,
skills and Memory are excluded. Selected items are historical Summary data under
the child's budget; they inherit neither pinning nor artifact re-read capabilities.
Source event/snapshot/item provenance survives in the child's persisted snapshot.
No journal mutation occurs when constructing the contributor; execution writes
only through the existing canonical Turn boundary. Scope-mismatched requests
receive no inherited items. Real child requests retain fresh state/current intent.

During agent execution artifact.read uses only scoped canonical roots and explicit
Core-authored output/summary references. Raw text hashes/stubs are not read grants.
The unscoped Session reader retains its existing separate behavior.
