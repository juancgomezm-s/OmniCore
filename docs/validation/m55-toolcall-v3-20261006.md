## Contrato

`toolcall.started` escribe schema 3. Conserva el constructor y deconstructor de
tres argumentos (`ToolCallId`, `EffectClass`, `ReconciliationJson`). Añade
propiedades init:

- `Reversibility`: `Unknown=0`, `Reversible=1`, `Compensatable=2`, `Irreversible=3`.
  Es independiente de idempotencia y reconciliación. No se deriva de EffectClass.
- `TargetRef: string?`: representación limitada del único claim de escritura
  filesystem, relativo al workspace de origen. No es una referencia universal,
  URI, hash CAS ni contrato de destinos de proceso/red. El runtime registra el
  claim único y deja null ante cero/múltiples targets; no elige el primero de varios.
  No añade autorización, validación de paths ni garantía de que ocurrió el efecto.
- `BeforeStateRef: ArtifactRef?`: reutiliza la referencia durable existente. Cuando
  está presente se indexa también en `DomainEvent.ArtifactRefs`, conservando la raíz
  para verificación/GC. Null no significa archivo vacío ni ausencia previa.

Upcasters v1→v2→v3 preservan el JSON histórico; los campos nuevos quedan
Unknown/null sin inferir reversibilidad por hashes pre/post. No se reescribe el journal.

## Alcance pendiente al guardar el contrato, sin éxito simulado

El bloque posterior implementa la captura filesystem normal y documenta sus
límites y pruebas en [captura preimagen](m55-filesystem-preimage-20261006.md).
Las observaciones siguientes corresponden al estado del commit 7cde78c.

El runtime todavía no captura preimágenes: sus eventos normales mantienen
Reversibility.Unknown y BeforeStateRef null. La prueba SQLite usa una referencia
de texto explícita de fixture para verificar contrato, atribución, indexación y GC;
no acredita captura automática ni fidelidad binaria de un archivo real.

La auditoría comprobó que `IArtifactStore` solo expone PutText/GetText/Verify.
PutText aplica redacción y UTF-8, por lo que no preserva automáticamente bytes de
un archivo con BOM/UTF-16 o contenido sensible. Sensitivity.Sensitive no cifra.
No se añadió una escritura raw que eluda esa protección. Falta definir/cablear
la captura fiel, su política de contenido sensible y el fallo previo al efecto;
no basta guardar el hash de reconciliación ni base64 sin inspección del original.
Destinos no-filesystem/múltiples y su clasificación siguen sin esquema en el ADR.
