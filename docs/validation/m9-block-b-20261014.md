# Acta M9-B — lease, recibos y replay recuperable

**Estado:** listo para revisión e integración en `main`; M9 continúa abierto.  
**Rama:** `codex/m9-recovery`.  
**Entorno verificado:** Windows, almacenamiento local. Linux, macOS y filesystems de red no se han probado.

## Entrega

M9-B añade ownership exclusivo de escritura por Session mediante un lock OS permanente, reclamable
cuando muere el proceso. El store conserva el path del lock y nunca lo elimina o recrea. Los hosts que
sólo consultan pueden abrir el workspace ocupado; cada transición a escritura vuelve a adquirir la
exclusión y revalida Session/proyección. Append, purge, mantenimiento y operaciones de worktree sujetas
a mutación participan en el mismo ownership. Los cierres liberan los locks aunque falle el cleanup;
un rollback de adquisición suelta sólo los locks recién tomados.

Commands stdio usan receipts durables ligados a command ID, hash del JSON y scope; el receipt fija la
Session original. Un duplicado idéntico devuelve el resultado ya guardado y un ID reutilizado con otro
contenido se rechaza. Un receipt reservado que no llegó a completarse produce `unknown`; el lookup no
reenvía el command. Las receipts guardan metadatos/resultados acotados, no el payload del usuario.
Purgar una Session deja tombstone para impedir reejecución de IDs antiguos e informa gaps al replay.

`events.replay.page` conserva un high-water capturado al iniciar el replay, pagina con límite SQL,
comprueba discontinuidades y reduce el prefijo hasta que el envelope completo cabe en el límite UTF-8
del frame. La operación legacy `subscribe` mantiene su respuesta completa. El cliente retiene la
negociación de capabilities, usa páginas sólo si se anunciaron y cae a `subscribe` para Host 1.0 que
sólo ofrezca replay legacy. Vacío es replay vacío y completo. El transporte mantiene el comando CLI
`omni stdio input <texto>` y las consultas `omni stdio query <read-model>` conectados a un Host hijo
real y persistente; `omni host --stdio` sirve como entrypoint del Host. Continúan disponibles las rutas
in-process y la TUI.

Las focales incluyen exclusión con stores/procesos independientes, reclamación al morir el dueño,
fallo de sweep sin revocar leases previos, una receipt completada cuyo ACK no se consume antes de

aislado antes de terminar el hijo. No prueba una caída de energía ni atomicidad de todos los efectos
externos.

## Límites que permanecen

Esto no ofrece exactly-once general: un command externo ambiguo permanece `unknown`, sin reejecución
automática. Replay es por petición/páginas, no push; no se declara backpressure o reconexión universal.
No están construidos el grant seguro de origen humano externo, el consumidor TypeScript/Electron y su
supervisor, `media.read`, controles de procesos persistentes ni ConPTY. `Protocol`/`Client` siguen sin
dependencias exclusivas de net10. La verificación OS se limita a Windows local; no se ha probado Linux.
Esta acta acredita sólo el bloque M9-B, no el cierre de M9.
