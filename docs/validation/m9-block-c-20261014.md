# Acta M9-C — consumer TypeScript y supervisor Electron read-only

Estado: **bloque implementado en una rama separada de OmniCoder; pendiente revisión/integración por root**. M9 completo permanece abierto. Esta entrega no modifica fuentes ni contrato de OmniCore; consume stdio 1.0, los goldens y los DTO publicados por el bloque M9-B.

## Frontera implementada

`OmniCoreStdioClient` corre en Electron main y habla JSONL v1.0 con UTF-8 estricto, framing máximo de 1 MiB, correlación, negociación de capabilities, queries, ACK tipado (incluye `outcome:null` legacy), lookup de recibos y replay paginado con sesión/high-water/cursor. El hash usa los bytes de la representación canónica JSON realmente enviada. Las operaciones se serializan; errores/cancelación no reenvían commands. Ante ACK ambiguo el supervisor consulta el resultado por ID y hash: `Unknown` queda visible, sin retry ciego. El test peer verifica exactamente 1 command + 1 lookup Unknown, sin reenvío; la prueba Core de M9-B conserva su evidencia independiente de persistencia real.

El supervisor inicia sólo el entry local configurado/descubierto con argv separado, `shell:false`, cwd físico validado, timeout y cleanup de procesos propios. Stderr se limita y sanea; stdout contiene sólo protocolo. `connect` reserva workspace antes de spawn, pues Host puede ejecutar recovery escritor durante startup; la liberación sucede tras salida confirmada. Una conexión activa bloquea operaciones legacy mutantes de ese workspace y el WorkerBridge/Goals global. El panel de Sidecar sólo presenta read models, funciones negociadas e historial; consulta salud cada 2 s mientras el proceso se espera vivo y descarta respuestas tardías de otro workspace.

La superficie sólo ofrece conectar/desconectar/cambiar Host y lectura. No hay chat, respuesta de assistant, inferencia, input de usuario, autorización humana, envío de acciones externas, `media.read`, streaming/push o fallback Pi de un command aceptado. `sim` se usó sólo como comando determinista de prueba diagnóstica; no se interpreta como conversación. La elección Core es explícita por workspace; no se cambia backend al iniciar por defecto. Mientras Core está reservado, la restricción del bridge MCP es conservadora y global.

## Pendientes M9 y riesgos

El panel consume un snapshot y su replay inicial; no ofrece eventos push ni sincronización incremental continua. La lease multiproceso por Session pertenece al Host y está probada en el bloque B; la reserva de workspace Electron sólo coordina este producto y no excluye automáticamente aplicaciones externas al mismo workspace. Sigue pendiente aceptación multi-OS y verificación de filesystem local/red. El cierre M9 aún requiere autoridad humana externa segura equivalente a `ITrustedUserActionClient`, chat/model runtime, `media.read` a proveedor visual, procesos persistentes/ConPTY, más lectura/artifacts/telemetría/stream y paridad de producto. No se afirma exactly-once general.
