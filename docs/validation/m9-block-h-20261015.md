# M9-H — entrega continua de eventos por stdio

Fecha: 2026-10-15. Alcance: Core .NET/CLI y consumidor OmniCoder de eventos canónicos durables de OmniCore. Este bloque entrega la infraestructura de stream con suscripción opcional negociada, páginas/reanudación desde journal, control de flujo y el wiring de producto. No declara cerrado M9 ni M8.

## Contrato y límites

- La capacidad opcional `events.stream.v1` se negocia en `hello`; clientes 1.0 sin la capacidad conservan su comportamiento legacy. El host mantiene un único escritor serializado de stdout para que respuestas correlacionadas y eventos no se intercalen.
- `events.stream` suscribe, `events.stream.ready` confirma aceptación, `events.stream.ack` reconoce consumo y `events.stream.stop` detiene el stream. El cursor se interpreta en el espacio de secuencias durables del journal; el mapper puede filtrar eventos internos, y el cliente avanza al `nextSequence` de la página aunque la página visible esté vacía. ACK queda ligado a stream, Session y conexión actuales, sólo reconoce frames emitidos y consumidos, ACK repetido no da crédito adicional y no se permite saltar al futuro.
- Ventana permitida: 1–32 frames; límite de cada frame UTF-8: 1 MiB. El host sólo relee journal cuando existe crédito. Si el consumidor se retrasa, mutaciones y comandos no esperan por su callback; la lectura se pausa y se expone `gap` cuando ya no se puede reanudar íntegramente. El cliente .NET mantiene un canal acotado de 32 eventos y ACKea tras completar el callback consumidor.
- La lectura del host despierta con un intervalo acotado de 40 ms y sólo consulta páginas durables al tener crédito; el journal sigue siendo la fuente de verdad. El frame grande pasa por el límite protocolario, pero queda sujeto también a los límites físicos del proceso/transporte y memoria del sistema.
- Cancelación, EOF, stop y rebind liberan la suscripción y no permiten que un pump anterior publique bajo el ID de una suscripción nueva. El stream nunca reenvía comandos ambiguos ni eleva permisos de confirmación humana.
- Lo entregado son eventos canónicos del journal. No incluye streaming de tokens del proveedor ni inventa TTFT, usage o progreso. Si el host no negocia la capacidad, el consumidor usa la ruta legacy y no la etiqueta como push.

El caso focal ejecuta Host y cliente reales. Configura ventana 1, retiene el primer callback y prueba que una query correlacionada termina con la ventana llena y sin ACK; después libera el callback, observa un evento `session.input` nuevo antes del resultado final del Run, detiene y vuelve a suscribir al mismo Host con ID nuevo, y observa el siguiente evento sin mezcla de generaciones. La evidencia se limita a lo que ejecutaron esos 24 tests; los criterios enumerados en ADR-0054 no sustituyen casos aún no implementados ni prueban reconexión automática.

El consumidor TypeScript/supervisor está conectado a la proyección de estado y al adaptador de chat de OmniCoder; la aplicación serializa los eventos con el drain terminal y usa reconciliación final, sin replay periódico por tick. La E2E Electron→Host .NET con proveedor local determinista, ejecutada en el worktree Coder, pasó los dos escenarios revalidados (composer y `/images`) en la corrida final agrupada: log `%TEMP%\m9h-coder-two-e2e-f546ed588cfd4d5ab22b58c03e96a5d1\e2e.log`, código 0. Los otros cinco escenarios pasaron en una corrida previa separada; no se presentan como una suite única 7/7. El harness stubbeó la confirmación humana y aisló los directorios que esa corrida ya configuraba. El default de `OMNICORE_AGENT_HOME` bajo el store temporal se añadió después de la E2E y se compiló, pero no se volvió a correr GUI: no se atribuye retrospectivamente a la corrida. El chequeo de procesos de harness concluyó `NO_ORPHANS` en el mismo directorio (`no-orphans.log`).

La revisión de código/documentos cubrió ADR-0013/0019/0030/0038/0049/0050/0051, el protocolo stdio 1.0 y sus goldens, arquitectura §24, plan M9, y `CLAUDE.md`/`AGENTS.md`. Esa lectura fija el contexto y los criterios, no se presenta como una prueba adicional de runtime.

El inventario de arquitectura Coder pasó tras reconocer el helper de envío protegido: 37 archivos, 141 canales main, 141 preload y 139 bridge. No se repitió GUI después de la E2E agrupada. La prueba de lifecycle cubrió callbacks IPC cuando la ventana está destruida; los errores nativos observados en una corrida previa quedaron corregidos antes de la corrida final.
