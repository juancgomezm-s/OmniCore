## Reported failures and candidate changes

1. **CLI assembly boundary.** `CliAssemblyReferenceTests.Omni_assembly_references_only_allowed_projects` found a direct `OmniCore.Domain` IL reference from `OmniCore.Cli`; the allowed direct references remain Client, Host, and Protocol. The CLI now forwards bounded source bytes to the existing Host `conversation.import` command and leaves canonical parsing and validation in Host. No ArchitectureTests allowlist was broadened.
2. **Cleanup with an active workflow consumer.** The previous fixture's extra active task was not linked to the target ownership. The candidate adds a real `LaneWorktreeBound` consumer packet referencing the target worktree and preserves cleanup rejection while that consumer is active. Its contrast contains a genuinely unrelated active lane and expects integrated cleanup to proceed. Production checks validate the bound event against its typed TaskPacket and unique owner `LaneWorktreeCreated` record before treating it as a consumer.
3. **Workflow sandbox outcome.** On the old Windows CI source, the verifier completed but the test's unconditional `Assert.Single(WeakSandboxConsent)` failed. The test configured a Strong request; the code only proceeds to Weak after a typed pre-launch Strong-unavailable result, which is persisted as a consent request. Thus a successful verifier with no such request is a legitimate Strong path by the existing control flow; the old log does not itself contain a sandbox-strength field. The candidate now accepts the platform's actual outcome and still requires the signed consent path whenever Weak fallback is taken. A workflow-only internal test seam supplies a fixed Strong-unavailable preflight in one row; it does not change the wire contract or authority. After consent, the platform launcher runs the real verifier process at Weak. The other row leaves the real platform preflight and launcher untouched.
4. **Weak-consent readiness.** The Linux CI failure did not preserve enough receipt detail to establish its cause. Static inspection found that the public projection computed `weakSandbox` before checking whether the conversation runner was still active, while the response gate rejects an active runner. The candidate aligns the read model with that existing gate; trusted-action checks and authority remain unchanged. An opt-in internal callback pauses the exact invocation after its deferred receipt is durable but before its task completes. The stdio query must report `weakSandbox:none` while held, then pending after release, and the normal exact-scoped consent path completes. The callback is null on normal Host paths and adds no protocol surface.
