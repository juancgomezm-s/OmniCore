# M9-F2 — respuestas de imagen generadas (2026-10-15)

**Estado:** implementación y wiring terminados en el worktree `codex/m9-multimodal-core`,
pendientes de revisión/integración. La E2E con fixture pasa; no existe una ruta live de
generación de imagen configurada/verificada, por lo que no se declara aceptación live.
M9 sigue abierto, G no iniciado, audio/vídeo excluidos y M8 OR5 pendiente.

## Cambios entregados

- Perfiles efectivos y preferencias distinguen modalidad de salida. Preferencias puede
  derivar una conexión OpenRouter `/images` explícita, reteniendo referencia de credencial
  y CA TLS desde la conexión fuente sin copiar ni apropiarse del secreto. No se altera el
  provider de texto. El endpoint dedicado no recibe tools ni parámetros del dialecto chat.
- OpenAI Responses sólo anuncia/usa imagen si la ruta/dialecto declara esa capacidad; la
  ruta Codex no se trata como generadora por analogía con una API distinta. Precio de
  imagen desconocido conserva `Unknown`; uso/coste reportado se registra con procedencia.
  Cotas/configuración no se presentan como gasto observado. Consentimiento metered y
  budgets siguen activos para gasto nuevo.
- Host valida MIME contra firma y decodifica por completo PNG/JPEG antes de aceptar bytes.
  Guarda output binario en CAS y journal con identidad de resultado y ModelStep; codecs,
  verifier, GC, replay y recuperación mantienen las mismas referencias. WebP y formatos
  no implementados se rechazan.
- La TUI accede al resultado a través de facade/DTO in-process y ofrece abrir/guardar sin
  afirmar preview gráfica cuando el terminal no la soporta. OmniCoder recibe bytes
  autorizados y mantiene texto/imagen en orden. El estado Electron main→renderer usa una
  envoltura base64 versionada con límites y validación lineal, no serialización accidental
  de Buffer/`Uint8Array` como objeto. El botón Guardar invoca `omnicore:save-generated-image`:
  main compara toda la identidad con una imagen de la proyección canónica de la Session,
  Host relee el artifact autorizado, main vuelve a comprobar workspace/session/generación
  tras el diálogo nativo y sólo entonces escribe el archivo. Bytes/rutas del renderer no
  se aceptan como autoridad.
- Si el proceso cae después de guardar el ModelStep y antes de publicar el evento visible,
  la recuperación finaliza la publicación exacta desde bytes durables; no repite la llamada
  al proveedor bajo coste Unknown. También se deduplican resultados ya publicados antes de
  completar el Turn. Los budgets siguen bloqueando llamadas nuevas no cubiertas.

## Límites y pendientes

No hay configuración efectiva de proveedor/ruta de generación live verificada. No se afirma
disponibilidad de image generation en `/codex/responses`, ni se usa ChatGPT built-in como API
de Core. La E2E local no acepta routing/gasto pagado. Aceptación live requiere ruta con
capacidad efectiva y consentimiento/budget propios; no se creó cuenta ni credencial.

La aceptación visual TUI interactiva quedó pendiente: el intento de captura del driver real
para `commands` a 120×35 agotó la espera `LayoutAndDrawComplete` de 10 s (la prueba terminó
con fallo de aserción a los 10.626 s). Salida/captura del intento preservada en
`%TEMP%\omni-tui-visual-one.log`; no se presenta la fixture como sustituto. El acceso terminal queda vía acciones
explícitas y archivo validado, sujeto a capacidad gráfica local. La aceptación multi-OS y los
cuatro idiomas no se repitieron en este bloque. Audio/vídeo siguen excluidos, M9-G sigue sin
iniciar, OR5 autenticado permanece pendiente y M9 completo no está cerrado.
