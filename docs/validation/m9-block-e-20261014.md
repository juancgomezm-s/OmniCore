## Resultado

El composer existente de OmniCoder consume el Host real de OmniCore. Una acción humana confirmada
por Electron main envía un `conversation.start.user` una sola vez. Core persiste una entrada y admite
el Run antes de ejecutar el pipeline configurado de `OmniCliRuntime` sobre Session, Run, command e
intervalo de secuencias fijados. El command genérico `session.input` conserva su semántica anterior.
El ACK Accepted sólo significa admisión durable. `conversation.result` consulta el estado de ejecución
asociado al receipt sin reenviar; la respuesta y los estados terminales se recuperan del journal y
artifacts mediante replay con cursor/high-water. El consumer drena y deduplica el replay antes de
settled. No se presentan errores de provider como texto assistant ni se inventan tokens, TTFT,
consumo, coste o respuesta antes del evento canónico.

Pi sigue siendo el backend legacy explícito por workspace. Core usa sus propios providers, modelos,
routing y policies configurados; el selector de Pi no los controla. Estado y composer se mantienen
fenced por workspace/Host. El modo elegido sin Run se ata a la generación del supervisor y se borra
al desconectar, cambiar Host o reconectar. Las consultas continúan durante la inferencia y las
mutaciones/cancelación respetan la serialización del Host.

El adapter sólo restaura la Session Core actual. Crear, seleccionar, nombrar o compactar Sessions;
usar el selector de Pi para cambiar el modelo Core; adjuntar archivos; ejecutar ORQ; responder una
interacción del Host; y elegir un modelo Core desde esta UI no están soportados y no se ofrecen como
acciones activas.

## Límites restantes

No se implementó token streaming/push; el resultado final procede de replay. No se informan métricas
de provider que la respuesta final no acredita. `media.read`, controles de procesos persistentes y
ConPTY, procedencia Native/Imported, validación Linux/macOS/filesystems y aceptación nativa es/en/fr/it
continúan pendientes. No hay exactly-once general frente al provider: si el resultado es ambiguo se
consulta receipt/replay y no se reenvía. OR5 autenticado de M8 sigue pendiente. Estas limitaciones no
impiden el slice construido y no cierran M9.
